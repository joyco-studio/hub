## The problem

You have a single atlas image — a spritesheet, a texture map, a design comp — and you need to extract specific rectangular regions from it. Maybe you need those crops mapped onto other images. Maybe you need their coordinates exported as JSON for a renderer. Maybe both.

The usual workflow is painful: open Photoshop, eyeball coordinates, manually note pixel values, re-export every time something shifts. For game dev and WebGL work, where atlases are the standard unit of delivery, this cycle repeats constantly.

Atlas Cropper is a browser-based tool we built to replace that entire loop. Define crops visually, arrange them in a layout, export the config, and batch-extract UV crops — all from a single interface.

## How it works

The tool is organized into four sequential tabs, each handling one stage of the workflow:

### 1. Crop Definition

Upload an atlas image (drag-and-drop or file picker) and draw rectangular regions directly on it. Each crop gets a unique name and color for identification.

The editor behaves like you'd expect from a design tool:

- **Click and drag** to create or move crops
- **Grab handles** to resize (8-point: corners + edges)
- **Shift + drag** on a corner to lock aspect ratio
- **Alt + drag** on an existing crop to duplicate it
- **Arrow keys** to nudge (1px, or 10px with Shift)
- **Magnetic snapping** aligns crops to edges and centers of neighboring regions — toggle with `S`, bypass with `Alt`

The canvas is infinite. Middle-click drag to pan, `Ctrl+scroll` to zoom (cursor-centered). `Cmd+0` fits everything to view.

### 2. Layout Arrangement

Position your defined crops in 2D space. Each crop has `x`, `y`, and `z-index` coordinates. This is where you define how the crops relate to each other spatially — useful when your atlas regions need to be reassembled or composited in a specific arrangement.

Features carry over from the crop editor (snapping, pan/zoom, keyboard shortcuts), plus:

- **Origin controls** — define a reference point in absolute pixels or percentages
- **Constrain mode** — clamp crops within image bounds (`C` to toggle)
- **Background overlay** — 30% opacity atlas image for reference (`B` to toggle)
- **Sidebar reordering** — drag crop items to reorder draw priority

### 3. Output

Generates a JSON configuration that fully describes the atlas setup:

```json
{
  "atlasSize": { "width": 1024, "height": 1024 },
  "crops": [
    {
      "crop": { "x": 10, "y": 10, "width": 256, "height": 256 },
      "position": [0, 0, 0]
    }
  ]
}
```

- **`atlasSize`** — the canonical pixel dimensions of the source texture. Everything else is relative to this.
- **`crop`** — size and position of each crop region in atlas space (origin: top-left). This is where the region lives on the source image.
- **`position`** — where each crop lands in object space (`[x, y, z]`). Each crop positions itself relative to the defined object center, so the layout arrangement translates directly into spatial coordinates a renderer can consume.

One-click copy to clipboard. This is the bridge between the visual tool and whatever consumes the crop data — a game engine, a WebGL shader, a build pipeline.

### 4. UV Crop

Upload one or more base images and associate each with a defined crop. The tool scales the crop coordinates from the atlas dimensions to each target image's dimensions, then extracts the corresponding region.

- **Individual download** as PNG
- **Batch download** as a ZIP archive
- **Drag-and-drop** upload for base images

This is where atlas definitions become actual image files you can drop into a project.

## Why not just use Photoshop / Figma?

Two reasons:

1. **Structured output.** Design tools give you pixels. Atlas Cropper gives you a JSON config with exact coordinates and spatial relationships. No manual transcription of values into code.

2. **UV mapping.** The crop-to-image pipeline lets you define regions once on an atlas and then apply those regions to any number of target images. Resizing is handled automatically. This isn't something general-purpose design tools are built for.

The tool is purpose-built for the specific loop of: define regions on an atlas, export coordinates, extract those regions from other images. It does that loop well and nothing else.

## Use case: Compositing multi-layer overlays from a single atlas

You have a single high-res texture atlas — a character, a vehicle, a UI composition — with multiple visual layers baked into one image. You need each layer extracted as a separate lightweight image, positioned exactly where it belongs relative to the others. Without structured coordinates, you'd spend hours eyeballing positions in a design tool and manually transcribing pixel values into code.

Atlas Cropper turns that into a four-step pipeline. Here's a real example: extracting emission overlay layers from a mecha model atlas.

### 1. Crop Definition

Load the atlas (3880 × 5043) and draw crops around each region. Each crop isolates one layer — in this case, four glow overlays for head, chest, arm, and leg.

### 2. Layout Arrangement

Position each crop relative to a shared origin. The coordinates you define here are what a renderer consumes directly — no guesswork, no manual offset calculations.

### 3. Output

The JSON config captures everything — crop regions in atlas space and positions in object space:

```json
{
  "atlasSize": { "width": 3880, "height": 5043 },
  "crops": [
    {
      "crop": { "x": 946, "y": 354, "width": 1988, "height": 670 },
      "position": [-835.5, -1874.5, 0]
    },
    {
      "crop": { "x": 1316, "y": 1024, "width": 1248, "height": 831 },
      "position": [-465.5, -1205.5, 0]
    },
    {
      "crop": { "x": 629, "y": 2206, "width": 687, "height": 1900 },
      "position": [-1152.5, -25.5, 0]
    },
    {
      "crop": { "x": 2184, "y": 1855, "width": 538, "height": 1614 },
      "position": [399.5, -375.5, 0]
    }
  ]
}
```

One click to copy. A shader, a game engine, or a build script can place each fragment at the correct position without any manual coordinate transcription.

### 4. UV Crop

Upload the individual layer textures as base images and associate each with its corresponding crop. The tool scales the crop coordinates to each target image's dimensions and extracts the region.

<Figure src="/atlas-cropper-entry/UV-crop.png" alt="UV Crop tab showing an overlay layer extracted from its base image" width={1456} height={816} />

<Figure src="/atlas-cropper-entry/UV-crop-2.png" alt="UV Crop tab showing another overlay layer extracted from its base image" width={1456} height={816} />

Each extracted crop matches the exact dimensions defined in the config — drop them into a project and the coordinates line up without adjustment.

### Result

Feed the JSON config and the cropped fragments into a renderer and everything snaps into place. Each layer is lightweight, precisely positioned, and independently animatable — no manual alignment required.
